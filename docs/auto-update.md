# 자동 업데이트

> 상태: 작성됨(현황). 설치본 자동 업데이트를 구성했다(D-030, 2026-11-09). 레포를 공개해(2026-11-11, v1.0.0 게시) GitHub Releases 확인·내려받기가 설정 변경 없이 동작한다(2026-11-13 실제 피드 확인: 최신 1.0.1). 드로어를 열 때 확인·상태 표시는 D-048(2026-11-13).

## 업데이트 채널

<!-- sw:section id=update-channel source=- owner=user gate=no_placeholder -->
설치본(NSIS)은 **electron-updater**로 **GitHub Releases**(`postcat23/Cat-Talk`, `package.json`의 `build.publish`)를 채널로 쓴다. dev(`npm start`)는 업데이트를 확인하지 않는다. upstream bongo-cat-chat도 GitHub Release 채널을 쓴다.

- 확인: 앱을 켤 때, 2시간마다, 드로어를 열 때(버튼 없음). 새 버전은 백그라운드로 내려받는다(`autoDownload`).
  - 확인 중·내려받는 중·설치 준비됨이면 다시 묻지 않는다. 드로어 열기와 2시간 주기는 직전 확인을 시작한 지 30초가 안 됐으면 건너뛴다. [다시 시도]는 30초 간격만 건너뛴다.
- 드로어 '앱 업데이트'는 설치 버전 배지(`v1.0.1`)와 상태 문구, 버튼을 한 줄에 보인다. 상태는 배지 글자색으로 구분하고, 문구는 늘 테마 기본 글자색이다.

  | 상태 | 배지 색 | 문구 | 버튼 |
  |---|---|---|---|
  | 확인 중 | 회색 | 확인 중… | — |
  | 최신(dev 포함) | 초록 | 최신입니다 | — |
  | 내려받는 중 | 주황 | 새 버전 v{버전} 다운로드 중 N% | — |
  | 설치 준비됨 | 주황 | v{버전} 설치 준비됨 | [재시작하여 설치] |
  | 확인 실패 | 빨강 | 업데이트 확인 실패 | [다시 시도] |
  | 다운로드 실패 | 빨강 | 다운로드 실패 | [다시 시도] |

  확인 실패와 내려받기 실패는 electron-updater가 같은 `error` 이벤트로 알려, 내려받는 중이었는지로 나눈다. 내려받기 실패 뒤 [다시 시도](또는 드로어 열기)는 다시 확인해 처음부터 내려받는다.
- 게시: 버전 태그 `v<버전>`(`package.json` 버전과 같아야 한다)을 push하면 GitHub Actions(`.github/workflows/release.yml`, Windows 러너)가 처음부터 빌드해 GitHub에 초안(draft) 릴리스로 올린다. 사전 산출물(호환성 도구·패처)·사이드카 번들·설치본까지 만들고, 자산(설치본·`.blockmap`·`latest.yml`)을 확인한다. 토큰은 워크플로의 자동 `GITHUB_TOKEN`만 쓴다(별도 시크릿 없음). 릴리스 본문 작성과 게시(Publish release)는 GitHub 웹에서 한다 — 게시해야 설치본이 내려받는다. 로컬 빌드만 할 때는 `npm run dist`(게시 안 함).

## 적용·롤백

<!-- sw:section id=update-apply source=- owner=user gate=no_placeholder -->
내려받기가 끝나면 드로어를 열지 않아도 대화 영역에 '새 버전 v{버전} 준비됨' 토스트와 [업데이트]가 뜬다(D-039). 드로어 '앱 업데이트'에도 'v{버전} 설치 준비됨'과 [재시작하여 설치]가 보인다. 토스트 [업데이트]든 드로어 [재시작하여 설치]든 사이드카(worker)를 정상 종료한 뒤 조용히 설치하고 앱을 다시 실행한다. 누르지 않아도 다음에 앱을 정상 종료할 때 설치된다.

- 메시지를 보내는 중이면 끝날 때까지 [업데이트]를 막는다. 입력창에 쓰던 글이 있으면(앱을 끄면 사라지는 설계, D-024) '입력 중인 글은 사라집니다' 확인 카드에서 한 번 더 [업데이트]를 눌러야 적용한다. 확인 카드가 떠 있는 동안 준비됨 토스트는 숨고, ×로 취소하면 다시 보인다.
- 상자 자동 오픈 설치·원본 복원 진행 카드가 떠 있는 동안(끝난 뒤 결과 문구 5초 포함)에는 준비됨 토스트와 확인 카드를 숨기고 드로어 [업데이트]도 막는다. 재시작이 게임 패치 흐름(게임 재실행·확인·되돌리기)을 끊지 않게 하기 위해서다.
- 준비됨 토스트의 X는 이번 실행 동안만 숨긴다(드로어 경로는 그대로). 설치하지 않은 채 다시 켜면(강제 종료·설치 실패 등. 정상 종료는 그때 설치한다) 시작 확인이 내려받아 둔 파일로 다시 '준비됨'을 알려 토스트가 한 번 더 뜬다. 시작 확인이 실패하면(오프라인 등) 다음 확인(2시간마다·드로어를 열 때·[다시 시도])이 성공할 때까지 토스트는 뜨지 않는다.
- 서명하지 않은 설치본은 업데이트 파일의 서명 검증을 하지 않는다(electron-updater 6.8.x는 `app-update.yml`에 `publisherName`이 없으면 생략하고 해시만 검증한다). 서명을 도입하면 electron-builder가 `publisherName`을 기록해 검증이 켜진다.
- 롤백: 자동 롤백은 없다. 문제가 있으면 이전 버전 설치 파일(GitHub Releases)로 수동 설치한다. 데이터 폴더(`%LOCALAPPDATA%\CatTalk`)는 설치·업데이트와 별개로 유지된다.
