# 아키텍처

Cat-Talk의 구조와 각 구성요소의 책임, 데이터가 흐르는 길을 정리한다. 프로세스 사이의 메시지 형식은 [ipc-contract.md](ipc-contract.md)에 있다.

## 구성 원칙

<!-- sw:section id=arch-principles source=src,lib owner=doc-team gate=no_placeholder -->
| 선택 기술 | 이유 |
|---|---|
| Electron + React 셸 | 메신저 화면을 웹 기술로 만들어 데스크톱 창·트레이로 제공한다. 모바일은 불가능해 크로스플랫폼 프레임워크의 이점이 없다 |
| Python 사이드카 유지 | 검증된 Steam 연동·게임 메모리 읽기 계층(Python)을 다시 쓰지 않고 그대로 쓴다 |
| Windows 전용 | 로컬 게임 프로세스·`steam_api64.dll`·Mono 런타임에 묶여 있어 다른 OS·모바일은 지원할 수 없다 |

- **원본 소스는 고치지 않는다.** 원본(bongo-cat-chat)의 Python 소스(`src/bongo_chat`)는 그대로 두고, 바꿀 동작은 `sidecar/`의 글루(상속·모듈 속성 교체)로 넣는다.
- **대화는 남기지 않는다.** 채팅·입퇴장 기록은 메모리에만 두고, 디스크에는 설정과 사용자가 직접 정한 값(닉네임·앱 차단)만 저장한다.
- **게임을 바꾸는 기능은 선택이다.** 기본 기능(채팅)은 게임 메모리 읽기와 Steam 로비 채팅 송신만 한다. 게임 파일을 패치하는 기능은 기본으로 꺼져 있고, 켤 때 원본을 백업한다.

### 범위 밖

- 게임 캐릭터 위 말풍선 표시
- 앱이 꺼져 있던 동안의 과거 대화를 서버에서 복원

## 책임과 컴포넌트

<!-- sw:section id=arch-components source=src,lib owner=doc-team gate=min_items:1 -->
| 구성요소 | 처리 |
|---|---|
| Electron main (`electron/`) | 화면 끝에 붙는 창·트레이·단일 실행, 사이드카 실행·종료, 자동 업데이트, 알림(토스트·작업 표시줄 배지), 선택 기능의 게임 패치 관리 |
| React 렌더러 (`renderer/`) | 메신저 화면 — 대화·검색·참여자·반응 카드·설정 드로어·알림 카드 |
| Python 사이드카 (`sidecar/` + `src/bongo_chat`) | 채팅 서비스(원본 코드) + 저장 글루. 렌더러 요청(대화 보기·보내기·설정·차단 등)에 답하고 worker를 띄운다 |
| worker (사이드카의 자식 프로세스) | 게임 프로세스 찾기·메모리 읽기(읽기 전용), 게임의 `steam_api64.dll`로 로비 채팅 송수신·멤버 프로필 읽기, 게임 에셋으로 고양이 아바타 합성, 연결 전 게임 빌드 호환성 확인 |
| 게임 패처 (`tools/auto_chest`) | 선택 기능용 IL 패처(Mono.Cecil). 게임의 `Assembly-CSharp.dll`을 패치한다. main이 원본을 백업하고, 설치 전에 별도 사본으로 패치해 Cat Talk 연결 호환성 지문이 그대로인지 확인한다 |

- 설치본은 사이드카를 PyInstaller로 묶은 실행 파일로 띄워 Python이 필요 없다. 소스에서 실행할 때는 시스템 Python 3.11을 쓴다.
- dev 실행과 설치본은 같은 사용자 폴더(`%APPDATA%\Cat Talk`)로 단일 실행 잠금을 공유한다. 이미 켜져 있으면 두 번째 실행은 첫 창을 펼치고 아무것도 띄우지 않은 채 끝난다.

## 데이터·상태 흐름

<!-- sw:section id=arch-dataflow source=src,lib owner=doc-team gate=no_placeholder -->
```
React 렌더러  ◀── IPC(contextBridge) ──▶  Electron main  ◀── stdio JSON 라인 ──▶  Python 사이드카
                                              │                                      │ 프로세스 큐
                                              │                                      ▼
                                              │                                   worker ──▶ 게임 프로세스(메모리 읽기)
                                              │                                      └─────▶ Steam 로비 채팅(steam_api64.dll)
                                              └──▶ 게임 폴더: 패치한 DLL·기능 플래그·숨김 목록 파일(선택 기능)
```

| 흐름 | 내용 |
|---|---|
| 렌더러 ↔ main | preload가 `window.bridge`(사이드카 요청 전달)와 `window.catTalk`(창·알림·업데이트·게임 패치)을 노출한다 |
| main ↔ 사이드카 | 표준 입출력의 JSON 한 줄씩. 요청·응답은 id로 짝짓고, 요청이 아닌 알림 줄(예: 게임 고양이 숨김 목록)도 오간다 |
| 사이드카 ↔ worker | 프로세스 큐. worker가 상태·메시지·반응·멤버 정보를 이벤트로 보내고, 사이드카는 보내기·새로고침 명령을 넣는다 |
| 저장 | 대화·세션·입퇴장은 메모리 DB에만 둔다(앱을 끄면 사라짐). 설정 DB(`settings.sqlite3`)와 창 위치(`window-state.json`)는 데이터 폴더 `%LOCALAPPDATA%\CatTalk`에 둔다. main이 이 폴더를 정해 사이드카에 넘긴다 |
| 선택 기능 | main이 패처로 게임 DLL을 패치하고(원본 백업은 데이터 폴더), 게임 폴더의 기능 플래그 파일과 숨김 목록 파일로 켜고 끈다. 패치된 게임이 이 파일들을 확인한다(투명화 플래그·숨김 목록은 0.5초마다) |
| 업데이트 | main이 GitHub Releases에서 새 버전을 확인해(켤 때·2시간마다·드로어를 열 때) 백그라운드로 내려받고, 사용자가 [업데이트]·[재시작하여 설치]를 누르거나 앱을 정상 종료할 때 설치한다 |

## 기술 한계

- Windows x64 전용이다. 게임 프로세스·`steam_api64.dll`·Mono 런타임에 묶여 있다.
- 게임 프로세스 메모리를 읽으므로 게임이 업데이트되면 주소·타입 구조를 다시 검증해야 한다. worker는 연결 전에 게임 빌드의 호환성 지문을 확인하고, 지원하지 않는 빌드면 연결을 멈춘다.
- 선택 기능의 게임 패치는 Steam 업데이트나 '게임 파일 무결성 확인'으로 원본으로 돌아갈 수 있다. 그러면 앱이 다시 적용할지 묻는다.
- 대화는 앱을 켜 둔 동안만 받는다. 앱이 꺼져 있던 동안의 대화는 볼 수 없다.
- 코드 서명이 없어 설치할 때 Windows 보안 경고가 뜨고, 백신이 오탐할 수 있다([installation.md](installation.md)).
- 게임의 이용약관·안티치트 정책과의 관계는 사용자가 직접 검토해야 한다.
